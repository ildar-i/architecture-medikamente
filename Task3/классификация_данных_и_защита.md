# Классификация данных и стратегия защиты

## 1. Классификация данных

| Категория данных | Уровень конфиденциальности | Примеры данных | Состояние данных | Профиль риска |
|------------------|---------------------------|----------------|------------------|---------------|
| Медицинские данные | Критический | Медицинские карты, диагнозы, результаты анализов, заключения врачей, история болезни | At Rest, In Transit, In Use | Высокий |
| Персональные данные (PII) | Высокий | ФИО, дата рождения, паспортные данные, адрес прописки, телефон, email, место работы/учёбы | At Rest, In Transit, In Use | Высокий |
| Биометрические данные | Критический | Отпечатки пальцев, фото, генетические данные | At Rest, In Transit | Критический |
| Финансовые данные | Высокий | Номера банковских карт, платёжные реквизиты, история платежей, финансовые операции | At Rest, In Transit | Высокий |
| Данные о здоровье | Критический | Хронические заболевания, аллергии, группа крови, резус-фактор | At Rest, In Transit, In Use | Критический |
| Аналитические данные | Средний | Агрегированные статистические данные, отчёты без персональных данных | At Rest, In Transit | Средний |
| Метаданные | Средний | Логи доступа, метаданные файлов, временные метки | At Rest, In Transit | Средний |
| Служебные данные | Низкий | Конфигурационные файлы, системные логи (без PII) | At Rest, In Transit | Низкий |

## 2. Обоснование необходимости защиты

### 2.1 Медицинские данные (Критический уровень)

**Необходимость защиты:**
- Содержат медицинскую тайну, защищённую законодательством РФ
- Нарушение конфиденциальности может нанести серьёзный вред репутации и здоровью пациента
- Требования 152-ФЗ "О персональных данных" и специальных требований к медицинским данным
- Риск шантажа, дискриминации, утечки коммерческой информации

**Последствия утечки:**
- Репутационные потери компании
- Финансовые штрафы (до 18 млн руб. по 152-ФЗ)
- Уголовная ответственность
- Потеря доверия клиентов
- Возможные судебные иски

### 2.2 Персональные данные (PII) (Высокий уровень)

**Необходимость защиты:**
- Требования 152-ФЗ "О персональных данных"
- Риск кражи личности, мошенничества
- Возможность несанкционированного использования данных третьими лицами
- Требования GDPR (если есть иностранные клиенты)

**Последствия утечки:**
- Финансовые штрафы
- Репутационные потери
- Возможность мошенничества с использованием украденных данных
- Нарушение прав граждан

### 2.3 Биометрические данные (Критический уровень)

**Необходимость защиты:**
- Особый режим защиты по 152-ФЗ
- Невозможность изменения биометрических данных
- Высокий риск использования для мошенничества
- Требования специальных нормативных актов

**Последствия утечки:**
- Критические репутационные потери
- Максимальные штрафы
- Высокий риск мошенничества
- Невозможность восстановления безопасности

### 2.4 Финансовые данные (Высокий уровень)

**Необходимость защиты:**
- Требования PCI DSS (если обрабатываются карты)
- Защита от мошенничества
- Финансовая безопасность клиентов
- Требования Центробанка РФ

**Последствия утечки:**
- Финансовые потери клиентов
- Потеря лицензий на обработку платежей
- Репутационные потери
- Судебные иски

### 2.5 Данные о здоровье (Критический уровень)

**Необходимость защиты:**
- Медицинская тайна
- Возможность дискриминации
- Психологический вред пациенту
- Требования профессиональной этики

**Последствия утечки:**
- Серьёзный вред репутации
- Возможные судебные иски от пациентов
- Нарушение профессиональной этики
- Потеря лицензии на медицинскую деятельность

## 3. Инструменты защиты данных

### 3.1 Шифрование данных At Rest (при хранении)

| Категория данных | Инструмент | Технология | Обоснование |
|------------------|------------|------------|-------------|
| Медицинские данные | PostgreSQL TDE | AES-256 | Прозрачное шифрование на уровне БД, минимальное влияние на производительность |
| Персональные данные | PostgreSQL TDE | AES-256 | Единый механизм шифрования для всех PII |
| Файлы медицинских карт | MinIO/S3 Server-Side Encryption | AES-256 | Шифрование на уровне объектного хранилища |
| Резервные копии | Backup Encryption | AES-256 | Шифрование всех резервных копий |
| Данные на дисках | LUKS/dm-crypt | AES-256 | Шифрование на уровне файловой системы |
| Данные в Kubernetes | Kubernetes Secrets Encryption | AES-256 | Шифрование секретов в etcd |

### 3.2 Шифрование данных In Transit (при передаче)

| Категория данных | Инструмент | Технология | Обоснование |
|------------------|------------|------------|-------------|
| API запросы | TLS 1.3 | RSA/ECDSA + AES-GCM | Современный протокол с поддержкой Perfect Forward Secrecy |
| Внутренние сервисы | mTLS | TLS 1.3 с взаимной аутентификацией | Защита межсервисной коммуникации |
| Интеграция с лабораторией | TLS 1.3 + API Key | TLS + дополнительная аутентификация | Защита внешних интеграций |
| Мобильное приложение | TLS 1.3 + Certificate Pinning | TLS с фиксацией сертификатов | Защита от MITM атак |
| Веб-портал | HTTPS (TLS 1.3) | TLS 1.3 | Обязательное шифрование всех соединений |
| VPN для удалённого доступа | WireGuard/IPSec | Современные VPN протоколы | Защита удалённого доступа сотрудников |

### 3.3 Управление ключами шифрования

| Компонент | Инструмент | Технология | Обоснование |
|-----------|------------|-----------|-------------|
| Key Management | HashiCorp Vault | HSM или Software KMS | Централизованное управление ключами, ротация, аудит |
| Key Rotation | Автоматическая ротация | Политики ротации ключей | Регулярная смена ключей для снижения рисков |
| Key Storage | HSM (опционально) | Аппаратный модуль безопасности | Максимальная защита ключей для критических данных |
| Key Backup | Зашифрованные бэкапы | Шифрование бэкапов ключей | Восстановление в случае сбоя |

### 3.4 Контроль доступа

| Компонент | Инструмент | Технология | Обоснование |
|-----------|------------|-----------|-------------|
| Аутентификация | OAuth 2.0 / OIDC | JWT токены | Современный стандарт аутентификации |
| Авторизация (RBAC) | Spring Security | Role-Based Access Control | Разграничение доступа по ролям |
| Авторизация (ABAC) | Custom ABAC Service | Attribute-Based Access Control | Контекстная авторизация (время, место, устройство) |
| Многофакторная аутентификация | TOTP/SMS | 2FA/MFA | Дополнительная защита для доступа к критическим данным |
| Single Sign-On | Keycloak | SSO решение | Единая точка входа для всех систем |

### 3.5 Аудит и мониторинг

| Компонент | Инструмент | Технология | Обоснование |
|-----------|------------|-----------|-------------|
| Audit Logging | ELK Stack (Elasticsearch, Logstash, Kibana) | Централизованное логирование | Полный аудит всех операций с данными |
| SIEM | Wazuh / Splunk | Система анализа безопасности | Выявление аномалий и атак |
| Мониторинг доступа | Prometheus + Grafana | Метрики и дашборды | Мониторинг в реальном времени |
| Алертинг | AlertManager | Уведомления о событиях | Немедленное реагирование на инциденты |
| Data Loss Prevention | DLP система | Предотвращение утечек | Блокировка несанкционированной передачи данных |

### 3.6 Обфускация и обезличивание

| Компонент | Инструмент | Технология | Обоснование |
|-----------|------------|-----------|-------------|
| Tokenization | Custom Tokenization Service | Замена данных токенами | Защита данных в не-продакшн окружениях |
| Pseudonymization | Python библиотеки (Faker, etc.) | Псевдонимизация | Обезличивание для аналитики |
| Data Masking | Dynamic Data Masking | Маскирование в реальном времени | Защита данных при отображении |
| Anonymization | k-anonymity, l-diversity | Статистические методы | Полное обезличивание для BI/ML |

### 3.7 Управление жизненным циклом данных

| Компонент | Инструмент | Технология | Обоснование |
|-----------|------------|-----------|-------------|
| Data Retention | Automated Retention Policies | Политики хранения | Автоматическое удаление по истечении срока |
| Right to be Forgotten | Data Deletion Service | Безопасное удаление | Реализация права на забвение |
| Data Lineage | Apache Atlas / Custom | Отслеживание происхождения | Полная трассировка данных |
| Backup Management | Automated Backup Policies | Политики резервного копирования | Управление резервными копиями |

## 6. Приоритизация внедрения

### Фаза 1 (Критично - 1-2 месяца)
1. TLS 1.3 для всех соединений
2. Шифрование БД (PostgreSQL TDE)
3. Базовый контроль доступа (RBAC)
4. Аудит доступа к данным
5. Key Management Service (HashiCorp Vault)

### Фаза 2 (Важно - 3-4 месяца)
1. mTLS для межсервисной коммуникации
2. ABAC для контекстной авторизации
3. DLP система
4. Data Lineage
5. Автоматическая ротация ключей

### Фаза 3 (Желательно - 5-6 месяцев)
1. HSM для критических ключей
2. Расширенная обезличивание для аналитики
3. Автоматизированное управление жизненным циклом данных
4. Расширенный SIEM с ML
5. Регулярное тестирование безопасности
